To speed up the full build of your project you can configure it to use either precompiled databases or shallow compilation.
Below are some examples of how to configure the uvm_ref_flow predefined project to work with these features.
Note that you can also use both these features in the same build configuration file (i.e. precompile a shallow compiled code). 

1. Precompilation support
Creates a snapshot (precompiled database / precompiled library) for a section of the project to be reused later. 
Loading a precompiled database is significantly faster compared to full build.

To use precompiled databases you need two build configurations (the names of the .build files are only given for clarity, any .build file can be used to save / load a precompiled database):
   * a precompiled_save.build config file to save the database. DVT assumes the source code for the precompiled database does not change.
   * a precompiled_load.build config file to load the database and compile other files on top of it.

The entire Precompilation Support documentation can be found here: https://eda.amiq.com/documentation/eclipse/sv/toc/application-notes/precompilation.html

Below are some examples on how to configure the precompilation support.

1.1. RTL precompilation

   * The .dvt/precompiled_1_save.build. You could also use it from the command line, for example: $DVT_HOME/bin/dvt_build.sh -lang vlog -cmd <project_root>/.dvt/precompiled_1_save.build
   * The .dvt/precompiled_1_load.build. Loads precompiled RTL, compiles verification code on top.

1.2. IP precompilation

   * The .dvt/precompiled_2_save.build configuration precompiles ahb & apb packages (for the purpose of this example we will treat those as separate IPs). You could use it from the command line, for example: $DVT_HOME/bin/dvt_build.sh -lang vlog -cmd <project_root>/.dvt/precompiled_2_save.build
   * The .dvt/precompiled_2_load.build. Loads precompiled IP and compiles remaining RTL and verification code.
   
    Note that +defines and +incdir are still needed in "precompiled_load" configuration as they are specific to each +dvt_init section and the precompiled database loading is a separate +dvt_init section.
    For the same reason you may have to re-compile some already precompiled files, for example files with `defines. 

1.3. Auto precompilation

	* The .dvt/precompiled_auto.build configuration precompiles the project in 3 different libraries (design_lib, ip_lib, working_lib).
	
	Note that +dvt_precompiled_db_auto_exclude+working_lib is used to exclude the invocation you are actively working on from being precompiled.

2. Shallow compilation
DVT collects and stores only the API of a project section, reducing build time and memory usage. Unlike precompilation, source code changes are allowed.

The entire Shallow Compilation documentation can be found here: https://eda.amiq.com/documentation/eclipse/sv/toc/application-notes/precompilation.html

Below are some examples on how to configure the shallow compilation.
All the examples show complex configurations where the +dvt_init sections handle not only shallow compiled code, but also fully compiled code.
Assuming you want to shallow compile an entire +dvt_init section (i.e. it consists only of RTL or IPs) you can use +dvt_shallow_compile+FILE+* 

2.1. Shallow compile RTL

   * The .dvt/shallow_compile_1.build configuration enables shallow compilation on all modules, except for the verification top module.
   
   Note that for shallow compiled modules DVT only keeps in the internal database the ports and parameters.
   The .dvt/shallow_compile_waivers.xml disables errors generated by hierarchical accesses containing shallow compiled modules.

2.2. Shallow compile IPs

   * The .dvt/shallow_compile_2.build configuration enables shallow compilation uart & uart_ctrl packages (for the purpose of this example we will treat those as separate IPs).

2.3. Shallow compile everything except of several packages

   * The .dvt/shallow_compile_3.build configuration enables shallow compilation on everything (+FILE+*) except of uart & uart_ctrl packages (for the purpose of this example we will treat those as separate IPs).

2.4. Shallow compile everything except of UVM components creation functions

   * The .dvt/shallow_compile_4.build configuration enables shallow compilation on everything (+FILE+*) except of elements (functions / modules) required to compute the Verification Hierarchy.
   
   Full details on each element to be excepted from shallow compilation can be found in the build configuration file.
   The .dvt/shallow_compile_waivers.xml disables errors generated by hierarchical accesses containing shallow compiled modules.
